# What's Changed

## New Features

### AsyncResultCleanupBatch

`AsyncResult__c` records pile up over time and nothing deleted them. This release adds `AsyncResultCleanupBatch`, a batch you schedule with the lib itself. It keeps two independent retention windows: one for failed results (you usually want those around longer for debugging) and one for the rest. Set either, or both. A track you don't configure is never touched.

```apex
Async.batchable(
        new AsyncResultCleanupBatch()
            .failedOlderThanDays(90)
            .othersOlderThanDays(30)
    )
    .asSchedulable()
    .name('AsyncResult Cleanup')
    .cronExpression(new CronBuilder().everyDay(3, 0))
    .schedule();
```

Retention is explicit (no silent default that deletes data), and deletes run in system mode so the job works whatever the running user's permissions are. See [AsyncResult Cleanup](https://async.beyondthecloud.dev/explanations/asyncresult-cleanup) (#2).

## Improvements

- `QueueableJob.className` is cached per instance, so the expected `TypeException` the framework uses to read a class name lands in the debug log once per job instead of on every access. The cache is `transient`, so a deserialized job always recomputes it from its own runtime type (#42).
